# Архитектура

## Компоненты

| Часть | Реализация и ответственность |
| --- | --- |
| iPhone | SwiftUI, iOS 26+, Swift 6 |
| Личные данные | SwiftData V8, совместимое чтение предыдущих схем |
| Базовый каталог | SQLite V2, SQLite3, чтение отдельно от личных данных |
| Голос | Parakeet TDT v3 через FluidAudio / Core ML |
| Разбор приёма | Локальный MealPairParser, еда и количество |
| Разбор этикетки | RussianLabelParser, редактируемые показатели |
| Семантический поиск | multilingual E5 small, локальный Core ML |
| Исторический облачный путь | MealAPI / Polza для прежних диктовок |
| Виджеты | WidgetKit и отдельный снимок агрегатов в общей Keychain-группе |
| Подготовка данных | Python; в iOS-приложении Python не используется |

Новая диктовка: микрофон → VoiceSession / VoiceEngine → Parakeet → локальный
разбор → поиск кандидатов → редактируемые MealRow → подтверждение → дневник.
Qwen / MLX остаётся экспериментальным кодом и автоматически не вызывается.

## Контракты данных

MealRow имеет собственное имя, необязательную карточку, количество, единицу
и частичный снимок КБЖУ на порцию. NutritionSummary считает известную сумму
и пропуски отдельно по каждому нутриенту. Расчёты используют Decimal;
округление выполняется при отображении. Энергия источника не заменяется
расчётом по белкам, жирам и углеводам.

Каталог поставщика, личная карточка и запись дневника имеют разные жизненные
циклы. Подтверждённая запись хранит снимок значений. Обновление каталога
не пересчитывает историю. Ведущие нули штрихкода сохраняются.

WorkDraft хранит независимую работу над приёмом, продуктом, рецептом,
приготовлением или сочетанием. Подтверждение записи, движения партии
и закрытие выбранного черновика атомарны. Повтор подтверждения не должен
дублировать порции. Асинхронный результат применяется только к своему
идентификатору и ревизии; поздний ответ не подменяет текущую работу.

Ошибка открытия хранилища не разрешает удалить базу или заменить её пустой.
Миграции аддитивны; прежние UUID и исторические снимки сохраняются.

## Поиск, партии и фон

Catalog читает поставляемый SQLite только для чтения. ProductRepository
управляет личными карточками и поисковыми снимками. Кэши проверяют ревизии;
ошибка записи кэша не должна уничтожать пользовательские данные.

Партия хранит фактический состав и измеренный выход. Движение остатка связано
с UUID строки дневника. Исправление старой строки не открывает выброшенную
или закрытую партию. План и рецепт не списывают еду.

DiaryReader получает снимки дней на отдельном исполнителе. Перелистывание
соседнего дня не изменяет выбранный черновик. Диагностика хранится локально
отдельно от фактов дневника и долговременного аудита операций.

Приложение не содержит развёрнутого сервера, аккаунтов или облачной
синхронизации. Сетевые границы описаны в [приватности](privacy.md).

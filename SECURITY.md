# Безопасность

Не публикуйте ключи, пользовательские базы, аудио, Health-данные,
диагностические архивы и персональные скриншоты в issues или pull requests.
Для сообщения о дефекте используйте минимальное синтетическое воспроизведение.

Если в репозитории настроен GitHub Private vulnerability reporting,
используйте вкладку Security → Report a vulnerability. Если такого действия
нет, не публикуйте чувствительные подробности: сначала запросите у владельца
закрытый канал, не прикладывая сами данные. Отдельный адрес поддержки здесь
не объявлен. До публикации maintainer должен проверить доступность этого пути.

При обнаружении действующего ключа отзовите или замените его. Удаление строки
из последнего коммита не удаляет её из истории и чужих копий.
[Порядок GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).

Политика хранения и внешние запросы описаны в [приватности](docs/privacy.md).
Автоматическая проверка секретов не заменяет проверку содержимого и вложений.
